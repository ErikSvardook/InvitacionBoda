01 · Resumen

De una invitación correcta a una invitación con atmósfera

La página ya tiene toda la información y funciona. Lo que sigue no es rehacerla: es darle una dirección de arte. El cliente pidió una paleta otoñal, degradados que se mezclen con las fotos, arcos, aire y una composición claramente alineada a la izquierda.

El rediseño se apoya en tres ideas sencillas:

01 · Atmósfera

Colores cálidos, degradados suaves y fotos tratadas con un velo ámbar. La página debe sentirse como una tarde de otoño, no como una plantilla.

02 · Composición

La información vive a la izquierda. Las imágenes respiran a la derecha, en marcos de arco. El texto deja de estar centrado en todas las secciones.

03 · Movimiento

Dos interacciones nuevas: la historia completa en un modal nativo y una galería con tres fotos visibles y avance circular.

02 · Dirección de arte

La paleta otoñal

La paleta actual ya era cálida, pero le faltaba saturación y contraste. La nueva versión toma los cinco tonos del moodboard del cliente y los convierte en tokens de Tailwind. No se escriben hexadecimales en los componentes: todo pasa por bg-cream, text-coffee, etc.

Cómo se construyen los degradados

No hace falta una imagen de fondo ni un SVG complejo. Los degradados se hacen con utilidades de Tailwind y con dos capas: una base lineal y un brillo radial difuminado. Así se obtiene el efecto de “luz de tarde” sin pesar en el rendimiento.

Base oscura

De ink a coffee, con un toque de cinnamon en la esquina. Se usa en Historia, Galería y Despedida.

Base clara

De cream a sand muy diluido, con un brillo terracotta al 10%. Se usa en Bienvenida, El Gran Día y Vestimenta.

Tratamiento de las fotos: cada imagen lleva un velo bg-linear-to-t from-coffee/45 via-transparent to-terracotta/10 para unificarla con la paleta, sin volverla sepia.

03 · Composición

Las reglas que ordenan todas las secciones

1. La información a la izquierda

El patrón dominante será: kicker, título serif, línea corta, párrafo y acción, todo alineado a la izquierda. Se abandona el centrado sistemático. El centrado se reserva para la cortina y para el pie de página.

2. Las fotos en arco

Los marcos de arco se construyen con rounded-t-full para un arco vertical, y con border-radius: 50% 0 0 50% / 50% 0 0 50% para el arco lateral que abre la Historia hacia la derecha.

3. El aire

Las secciones suben a py-24 y py-28. Las columnas usan gap-10 o gap-14. El lujo visual aquí no viene de agregar cosas, sino de dejar espacio.

4. Las líneas finas

La línea horizontal corta debajo de los títulos y la línea vertical junto a la fecha son el hilo conductor. Son de 1 px, color sand o terracotta, y nunca compiten con el texto.

5. La tipografía

Cormorant Garamond para títulos, nombres y números grandes. Montserrat para kickers, botones, párrafos y navegación. Se mantienen las fuentes actuales: no hay que instalar nada.

6. El móvil no es una copia reducida

En móvil, las columnas se apilan en este orden: texto, imagen, dato secundario. Los arcos se conservan, pero con menos altura. Los botones ocupan el ancho disponible y las fotos de la galería se muestran en una fila de tres cuadrados pequeños.

La fecha no se escribe a mano

Para que nunca se desincronice, se calcula desde event.dateIso con Intl.DateTimeFormat("es-MX", ...). El día de la semana también se deriva. Si el cliente cambia la fecha, la sección cambia sola.

// data/wedding-data.ts export const eventParts = (() => { const fecha = new Date(event.dateIso); const formato = (opciones: Intl.DateTimeFormatOptions) => new Intl.DateTimeFormat("es-MX", { timeZone: "America/Mexico_City", ...opciones, }).format(fecha); return { weekday: formato({ weekday: "long" }), day: formato({ day: "2-digit" }), month: formato({ month: "2-digit" }), year: formato({ year: "numeric" }), }; })();
El panel de la fecha no necesita JavaScript. Es un componente de servidor que lee eventParts. El único cliente de la sección sigue siendo el que necesite estado, si más adelante se agrega.

El arco lateral

El contenedor de la foto mide la mitad del ancho de la pantalla y toda la altura de la sección. El borde izquierdo se redondea con una elipse completa:

className="relative overflow-hidden lg:[border-radius:50%_0_0_50%/50%_0_0_50%] lg:[mask-image:linear-gradient(to_right,transparent,black_16%)]"

El mask-image hace que la foto se desvanezca hacia la izquierda y se funda con el degradado café. Sin la máscara, el corte del arco se vería duro. En móvil, la foto pasa debajo del texto y usa un arco superior normal (rounded-t-full).

El modal de la historia completa

Se abandona el <details>. El botón abre un <dialog> nativo: el navegador se encarga del foco, del fondo y de la tecla Escape. No se necesita una librería de modales.

// components/sections/ModalHistoria.tsx (cliente) "use client"; import { useRef } from "react"; import { history } from "@/data/wedding-data"; export default function ModalHistoria() { const dialogo = useRef<HTMLDialogElement>(null); return ( <> <button type="button" onClick={() => dialogo.current?.showModal()}> Conoce nuestra historia </button> <dialog ref={dialogo} onClick={(e) => { if (e.target === e.currentTarget) e.currentTarget.close(); }} className="m-auto w-[calc(100%-2rem)] max-w-2xl max-h-[85svh] overflow-y-auto rounded-2xl border border-sand/60 bg-cream p-0 text-ink backdrop:bg-ink/80 backdrop:backdrop-blur-sm" > ... <form method="dialog"> <button>Cerrar</button> </form> </dialog> </> ); }

El bloqueo del scroll del fondo se resuelve con una regla CSS muy corta, sin efectos de React:

body:has(dialog[open]) { overflow: hidden; }
Contenido: los párrafos de la historia completa se mudan a data/wedding-data.ts, dentro de un objeto history. Así el componente solo se encarga de mostrarlos y el texto se edita en un solo lugar.

La lógica del carrusel

No hace falta duplicar el arreglo ni usar una librería. Se guarda un índice de inicio y se calculan las tres fotos visibles con el operador módulo. El botón suma uno; cuando llega al final, el módulo lo devuelve a cero.

// Solo la idea central const [inicio, setInicio] = useState(0); const visibles = Array.from( { length: Math.min(3, galleryPhotos.length) }, (_, i) => (inicio + i) % galleryPhotos.length ); const siguiente = () => setInicio((i) => (i + 1) % galleryPhotos.length);

El lightbox sigue recibiendo el arreglo completo y el índice real de la foto. Por eso las flechas del teclado y los botones del modal siguen funcionando igual que hoy. El texto de cada foto se mantiene tal como está en galleryPhotos.

El marco cuadrado

Cada foto vive dentro de un cuadrado con un borde fino sand y un pequeño padding interior. Ese detalle es el que da la sensación de “foto enmarcada” y no de imagen pegada al borde. En móvil se muestran tres cuadrados pequeños en una fila; si el espacio es muy reducido, se pueden ver dos y medio para invitar a deslizar, pero la versión recomendada es tres.

Sin collage: se puede quitar la propiedad size de GalleryPhoto y de los datos. El nuevo componente no la usa. Si se prefiere no tocar los datos todavía, no pasa nada: queda como información sobrante.

11 · Hoja de ruta

Orden de implementación

El trabajo se divide en pasos pequeños para que puedas pegar, ver el resultado en el navegador y entender qué cambió antes de seguir. No se avanza al siguiente paso hasta que el anterior se vea bien.

  1. Paleta y estilos base Actualizar app/globals.css: nuevos hexadecimales, token camel y la regla del diálogo. Es el paso que cambia el ambiente de toda la página sin tocar componentes.
  2. Datos nuevos Agregar eventParts, history, featuredPhotos.welcome y la imagen del lugar. Verificar que la fecha siga saliendo correcta.
  3. Componentes compartidos Crear ArcoFoto y FechaVertical. Se prueban en la Bienvenida antes de reutilizarlos.
  4. Hero + Bienvenida Reordenar el Hero hacia la izquierda y montar las tres columnas de la Bienvenida. Es el primer bloque visual completo.
  5. Nuestra Historia + modal Aplicar el arco lateral, el fondo oscuro y el modal nativo. Probar Escape, clic en el fondo y foco del teclado.
  6. Cuenta regresiva + El Gran Día Alinear la cuenta regresiva, unir el cronograma vertical y eliminar la onda. Ajustar el Header.
  7. Galería Convertir el collage en carrusel de tres fotos. Probar el ciclo infinito, el lightbox y las flechas del teclado.
  8. Vestimenta + Despedida Quitar las fotos de vestimenta y alinear la despedida a la izquierda. Cierre visual.
  9. Repaso responsive y accesibilidad Revisar 360 px, 768 px, 1024 px y 1440 px. Comprobar foco, contraste, textos alternativos y reducción de movimiento.
Consejo de trabajo: después de cada paso, ejecuta npm run dev y revisa la sección en el navegador. Si algo se ve raro, revisa primero las clases de Tailwind: un typo en un token no lanza error, simplemente no genera CSS.

12 · Calidad

Accesibilidad, responsive y pruebas

Accesibilidad

  • El modal usa <dialog> nativo y se cierra con Escape.
  • El botón de la galería tiene aria-label y el carrusel anuncia cuántas fotos hay.
  • Las fotos inactivas del carrusel de Historia llevan aria-hidden.
  • Los botones de la galería son <button>, no div con onClick.
  • El foco visible se mantiene en terracotta.
  • Si el sistema pide reducir movimiento, el carrusel de Historia no avanza solo.

Responsive

  • 360–639: una columna, arcos con menos altura, fecha horizontal.
  • 640–1023: dos columnas en Bienvenida y El Gran Día; cronograma debajo.
  • 1024+: tres columnas en Bienvenida y El Gran Día; Historia 50/50.
  • 1440+: el contenido se queda en max-w-6xl; la foto de Historia sigue sangrando al borde.
  • Si la galería se ve muy apretada en 360, bajar de tres cuadrados a dos.

Checklist antes de dar por terminado

  • La fecha visible coincide con event.dateIso y el día de la semana es correcto.
  • El Hero deja respirar el texto y no tapa la cara de los novios.
  • El arco de Historia llega al borde derecho y se funde con el fondo.
  • El modal de Historia abre, cierra con Escape, con el botón y con clic en el fondo.
  • El modal no deja hacer scroll en la página de fondo.
  • La cuenta regresiva sigue actualizándose cada segundo y no rompe la hidratación.
  • La galería avanza de una en una y vuelve al inicio después de la última foto.
  • El lightbox muestra el texto correcto de la foto seleccionada.
  • Vestimenta no muestra fotos y el texto se entiende sin ellas.
  • El Header solo tiene cuatro enlaces y todos llevan a una sección existente.
  • npx tsc --noEmit y npm run lint terminan sin errores nuevos.
Tailwind falla en silencio: revisa los tokens (text-terracotta, no text-terracota), los espacios entre clases y los corchetes de los valores arbitrarios.

13 · Cierre

Lo que el cliente va a sentir

La página deja de ser una lista de secciones centradas y se convierte en una invitación con ritmo: una foto que abre, un texto que respira, un arco que guía la mirada, una banda oscura que baja el tono y una galería que invita a tocar.

Antes

Bloques centrados, collage, onda SVG, fotos de vestimenta y un acordeón de FAQ. Correcto, pero genérico.

Ahora

Dirección de arte otoñal, composición editorial, arcos, fecha vertical, modal y carrusel. Más cerca de una revista de boda.

Sin perder

La información sigue siendo la misma y la fecha sigue viviendo en un solo lugar. Lo que cambia es cómo se presenta.
